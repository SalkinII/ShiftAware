## Components to Enhance

### CalendarView + DateDropZone (Snap Feature)

**Current:** Templates can drop anywhere on a date.
**Needed:** Templates snap to end of previous shift in same lane.

**Implementation:**
1. Add `existingShifts` prop to DateDropZone (or compute internally)
2. In drop handler, calculate snap position
3. Show visual indicator of snap target

### Login Page (Access Codes)

**Current:** Single username/password or demo login.
**Needed:** Festival-scoped access codes.

**Implementation:**
1. Add `AccessCode` model: `code`, `festivalId`, `expiresAt`
2. Login accepts access code instead of/in addition to credentials
3. Session stores `festivalId` for scoping

### Publish Page (Stage 3)

**Current:** Stub page ("coming soon").
**Needed:** 2-stage publish workflow.

**Implementation:**
1. Add `status` field to Event: `DRAFT`, `PUBLISHED`
2. Add `status` field to Shift: `DRAFT`, `PUBLISHED`
3. Publish page shows unpublished shifts, confirm button
4. Publish triggers visibility for users

### Export Page (Pretty PDF)

**Current:** Basic export functionality.
**Needed:** Professionally formatted PDF.

**Implementation:**
1. New PDF template with better typography
2. Include festival branding/header
3. Member-friendly shift cards
4. Summary statistics

## Data Model Changes Needed

### New Model: AccessCode

```prisma
model AccessCode {
  id         String   @id @default(cuid())
  code       String   @unique
  eventId    String
  event      Event    @relation(fields: [eventId], references: [id])
  expiresAt  DateTime?
  maxUses    Int?
  usedCount  Int      @default(0)
  createdAt  DateTime @default(now())
}
```

### Event Model Changes

```prisma
model Event {
  // existing fields...
  status     EventStatus @default(DRAFT)
  accessCodes AccessCode[]
}

enum EventStatus {
  DRAFT
  PUBLISHED
  ARCHIVED
}
```

### Shift Model Changes
