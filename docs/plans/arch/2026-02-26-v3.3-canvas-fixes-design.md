## Section 1: ShiftBlockNode Content Redesign

### Problem

`DynamicShiftContent` uses `scale(1/zoom)` with CSS dimensions `width * zoom` x `SHIFT_NODE_HEIGHT * zoom`. CSS layout (flexbox, truncation) happens at these small dimensions before the transform scales them up. At zoom 0.1 with a 4-hour shift, layout space is ~80px x 46px. Items stack vertically via `flex-col` with height gating using `SHIFT_NODE_HEIGHT = 460` (wrong — actual CSS height is 46px). Result: time + token show and get cropped instead of member names (P1).

The v3.2 design specified width-driven horizontal layout with member names as P1 at max zoom-out. The implementation did height-based vertical stacking instead.

### Design

**Drop `scale(1/zoom)`.** Let React Flow handle zoom natively. The node renders at its flow-space dimensions (`width` x `SHIFT_NODE_HEIGHT`); React Flow's viewport transform scales it on screen.

**Use `ResizeObserver`** (per `docs/DESINGSUGGESTION_react-flow-resizeobserver-pattern.md`) to measure the node's actual rendered pixel dimensions. This works independently of zoom level and responds to user-driven resize automatically.

**CSS Grid with horizontal-first layout:**

```
Row 1: [Names .............. Time  +++]   grid-template-columns: 1fr auto
Row 2: [Shift Name    Count  Status    ]   only if measuredHeight permits
Row 3: [Avatars            Vote buttons]   only if measuredHeight permits
```

**Width-driven reveal thresholds** (measured screen pixels):

| measuredWidth | Row 1 content |
|---------------|---------------|
| < 40px | Colored bar only (lane identity) |
| >= 40px | Member names (truncated) |
| >= 140px | + time range right-aligned |
| >= 180px | + token after time |

| measuredHeight | Rows shown |
|----------------|------------|
| < 24px | Row 1 only (single line) |
| >= 24px | Row 1 + Row 2 |
| >= 48px | Row 1 + Row 2 + Row 3 |

Thresholds are approximate and should be tuned visually during implementation.

**Remove:**
- `DynamicShiftContent` component and `RevealItem` abstraction
- `scale(1/zoom)` transform, `width * zoom`, `height * zoom` sizing
- Height-based gating logic

**Keep:**
- Glass card appearance: `bg-white/80 backdrop-blur-sm border-l-4 shadow-[var(--shift-shadow)]`
- `NodeResizer` for admin resize
- `SHIFT_NODE_HEIGHT` constant for flow-space node sizing
- `memo` wrapper on `ShiftBlockNode`

**Files:**
- `components/features/LaneCalendar/nodes/ShiftBlockNode.tsx` — full content rewrite

## Section 2: Resize Handle Bug

### Problem

1. `handleResizeEnd` only accepts `{ width: number }` — ignores `node.position.x`. Left-handle resize updates position in React Flow but handler never reads it, so `startTime` stays unchanged and shift just gets shorter.

2. `ShiftBlockNode.tsx:347` has `p.width ?? (p as any).x ?? width` — uses position `x` as width fallback (wrong semantics, corrupts duration).

3. Toast shows generic "Failed to update shift" — `data.details` from Zod validation never extracted.

### Design

**Extend handler signature** to `{ width: number; x?: number }`.

In `ShiftBlockNode`, pass `{ width: p.width, x: p.x }` from React Flow's `ResizeParams`. Never use `x` as width fallback.

In `handleResizeEnd`:
- When `params.x != null`: derive `newStartTime = xToTime(snapX(params.x), eventStart)`. Compute duration from width, derive `newEndTime`.
- When `params.x` absent (right-handle only): use existing `node.data.startTime` + new duration.
- Send both `startTime` and `endTime` in PUT body.

**Toast improvement:**
- If `data.details` is array: `details.map(d => d.message).join('; ')`
- Else: `data.message || data.error || "Failed to update shift"`
- Add toast on early-return paths (`!node`, `!isShiftNodeData`)

**Files:**
- `components/features/LaneCalendar/nodes/ShiftBlockNode.tsx` — fix `onResizeEnd` call
- `components/features/LaneCalendar/hooks/useCanvasActions.ts` — extend `handleResizeEnd`
- `ShiftBlockData` type — update `onResizeEnd` signature

## Section 3: Canvas Drag-Drop Reload

### Problem

1. `LaneCalendarCanvas.tsx:187-189` — `useMemo` calls `setNodes([...laneNodes, ...shiftNodes])` on every `shiftNodes` reference change. After drag-stop: `onShiftUpdated` → cache invalidation → `refetchShifts()` → new `shiftNodes` → full node replacement discarding React Flow's in-flight position/selection state.

2. `LaneCalendarCanvas.tsx:192-204` — `fitView` depends on `[shiftNodes.length, fitView]`. Fires on refetch even when count unchanged (race conditions), resetting viewport zoom and pan.

### Design

**ID-based merge function** `mergeNodes(currentNodes, laneNodes, newShiftNodes)`:
- Lane/grid nodes: always replaced from `laneNodes` (static, no user state to preserve)
- Shift nodes: for each ID in `newShiftNodes`:
  - If same ID exists in `currentNodes`: keep `position` and `measured` from current, update `data` from API response
  - If new ID: add node
- Shift nodes in `currentNodes` but not in `newShiftNodes`: remove (deleted via API)

**fitView guard:**
- Replace `[shiftNodes.length, fitView]` dependency with `initialFitDone` ref
- `fitView` runs once when first non-empty shift load completes
- `fitView` runs when `eventId` changes (switching events)
- Never runs on refetch within same event

**Stable key:** Verify `ReactFlowProvider` and `ReactFlow` have no `key` tied to shifts hash.

**Files:**
- `components/features/LaneCalendar/LaneCalendarCanvas.tsx` — merge function, fitView ref guard
