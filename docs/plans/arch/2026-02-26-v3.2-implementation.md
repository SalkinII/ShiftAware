**Step 1: Fix the hour offset**

The ruler starts at `visibleStartHour = Math.floor(-flowToScreenX(0) / pixelsPerHourAtZoom)`. When `flowToScreenX(0)` returns the screen X of flow position 0, and the canvas is scrolled such that flow position 0 is visible, this should be 0.

The actual bug: The `totalHours` calculation (line 28) is `differenceInHours(eventEnd, eventStart) + 24`. If `eventStart` is, say, 2026-07-01T08:00, the first tick at `h=0` represents 08:00, not 00:00. The 00:00 of that day is 8 hours before the event start — which is at negative flow-X.

**The fix:** Include the hours from midnight of the first day. Change the tick generation to start from `startOfDay(eventStart)`:

In `TimeRulerPanel.tsx`, add import:
```typescript
import { format, addHours, differenceInHours, startOfDay } from "date-fns";
```

Then modify the tick loop to use the actual midnight start:

```typescript
// Calculate the offset from midnight to event start
const midnightStart = startOfDay(eventStart);
const hourOffset = differenceInHours(eventStart, midnightStart);

// Ticks start from midnight of the first day
for (let h = visibleStartHour; h <= visibleEndHour; h++) {
  const xBase = (h - hourOffset) * PIXELS_PER_HOUR; // Adjust for midnight
  const time = addHours(midnightStart, h);
  // ... rest of tick generation
}
```

Wait — actually the flow coordinate system has x=0 at `eventStart`. If we want 00:00 ticks visible, we need to allow negative X values in the ruler. But the lane zones start at x=0 (event start). This is a conceptual decision: should the ruler show time before the event?

Looking at the user's note: "time ruler and panel start an hour later than the 00:00 tick." This suggests the 00:00 tick should be visible. The simplest fix is to extend the tick generation to include negative hours (before event start) down to midnight of that day.

**Revised approach:**

```typescript
// In TimeRulerPanel, compute tick range including pre-event hours
const midnightStart = startOfDay(eventStart);
const preEventHours = differenceInHours(eventStart, midnightStart);

// Shift visible range to include pre-event hours
const adjustedStartHour = Math.max(
  -preEventHours,
  Math.floor(-flowToScreenX(0) / pixelsPerHourAtZoom) - preEventHours,
);

for (let h = adjustedStartHour; h <= visibleEndHour; h++) {
  const xBase = h * PIXELS_PER_HOUR;  // h can be negative
  const time = addHours(eventStart, h);
  // ...
}
```

This way, if event starts at 08:00, h=-8 represents 00:00 of that day, and xBase = -8 * 200 = -1600 (which is offscreen at default pan but visible if user scrolls left).

```typescript
export type CacheScope =
  | "shifts"
  | "assignments"
  | "templates"
  | "preferences"
  | "registrations";

/**
 * Dispatch cache invalidation event for event-scoped data.
 * Components listening on `shiftaware:cache-invalidate` will refetch.
 */
export function invalidateEventCache(
  eventId: string,
  ...scopes: CacheScope[]
) {
  const keys: string[] = [];
  for (const scope of scopes) {
    keys.push(scope, `${scope}:*`, `${scope}:event:${eventId}`);
  }

  window.dispatchEvent(
    new CustomEvent("shiftaware:cache-invalidate", {
      detail: { keys },
    }),
  );
}
```
