## Decisions Made

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Viewport reset fix | Controlled viewport | Most robust; prevents all reset classes |
| Algorithm scope | Full hardening | Complete all items, not just bugs |
| Seed execution | Manual step | Documented, user runs when ready |
| Attribute naming | `humanize()` utility | Works without schema changes; camelCase + snake_case → Title Case |
| Multi-select logic | `ONE_OF` operator | Extends existing rule system cleanly |

## Architecture Compliance

- All service-layer changes follow Route → Service → Repository pattern
- New utilities placed in `lib/utils/` (no business logic)
- UI components use existing design tokens and atom components
- Algorithm changes are pure functions — no Prisma in algorithm layer
- Tests follow existing patterns: mock Prisma for repos, mock repos for services, pure functions for algorithm
