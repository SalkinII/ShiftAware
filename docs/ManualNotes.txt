## Template-Based Lanes (2026-02-15) - PLANNING NEEDED
Current limitation: Shifts are grouped by type (MOBILE_TEAM/STATIONARY/SUPER) into lanes.
Problem: Multiple shifts of the same type land in the same lane, causing overlaps.

Desired behavior: Each template should get its own dedicated lane.
Example:
  - "Mobile Team North" → own lane
  - "Mobile Team South" → own lane
  - "Stationary Main" → own lane
  - "Stationary Gate" → own lane
(Instead of all "MOBILE_TEAM" in one lane, all "STATIONARY" in another)

Current data model limitation:
  - Shift.type field is enum (MOBILE_TEAM, STATIONARY, SUPER)
  - Lane derivation: deriveLanesFromTemplates() groups by template.type
  - No way to distinguish between templates of same type

Proposed solution (needs planning):
  1. Add Shift.templateId as lane discriminator (already exists, just not used for lanes)
  2. Update deriveLanesFromTemplates() to create one lane per template (not per type)
  3. Update coordinate mapping: yToLaneIndex needs template-based lookup
  4. Update drag/drop handlers to map to template lanes, not type lanes

React Flow supports this - just need to adjust lane generation logic.
Requires careful planning to maintain backward compatibility.

Files to review:
  - lib/types/lane.ts (deriveLanesFromTemplates function)
  - components/features/LaneCalendar/hooks/useLaneNodes.ts
  - components/features/LaneCalendar/hooks/useShiftNodes.ts (laneIndexMap)
  - components/features/LaneCalendar/hooks/useCanvasActions.ts (drop handler)
